# Design appearance and motion together

Use this guide during substantial interface creation or redesign, and when the owner asks the graphic-design and motion skills to work together. Read it before treating the visual composition as finished. This is an owner-directed workflow refinement dated 30 October 2026, not a measured claim about universal taste.

## One creative direction

The companion [Graphic Design skill](https://github.com/MikeyNu/agent-graphic-designer/blob/main/skills/graphic-design/SKILL.md) supplies visual art direction, composition, typography, color, imagery, working-interface structure, and critique. Web Motion Director supplies temporal structure, progress/input mapping, implementation, lifecycle, and temporal verification. Both should shape the same result from the beginning. This does not require multiple agents or a particular runtime.

Read the actual available companion when applicable. A repository link does not install a skill or grant tools. If it is unavailable, continue with the joint workflow below and the project's approved visual system. Do not falsely claim to have loaded the companion.

Beauty, expressive rhythm, atmosphere, play, and enjoyment are legitimate intentions. Motion does not need a quantified business benefit or a functional metaphor for every flourish. Retain an expressive effect when it makes the actual experience stronger. Quiet regions remain useful, but the smallest animation and the stripped composition are not automatically the best choices.

## Joint workflow

1. Inspect the brief, identity, visual references, task/state model, implementation conventions, input modes, and capability limits. Separate observed reference motion from proposals.
2. While arranging visual elements, identify stable anchors, changing objects, expressive regions, and quiet support. Design the starting, intermediate, and settled composition together. For faithful reconstruction, verify the supplied resting state without postponing all motion thinking until after construction.
3. Compare materially different visual/temporal ideas for major new directions. Do not apply an identical entrance recipe to three differently colored layouts. A narrow repair can use the established motion language.
4. Prototype a principal transition or signature scene early. Inspect it at normal speed, then revise crops, contours, content placement, timing, or choreography together. Do not declare the visual design locked before testing a motion-dependent relationship.
5. Extend the chosen relationships through related controls and flows. Keep one shared contract, reusable timing/easing decisions, and explicit ownership of animated properties. The companion's [shared UI and motion brief](https://github.com/MikeyNu/agent-graphic-designer/blob/main/skills/graphic-design/assets/interface-motion-brief.md) is an optional working template.
6. Verify the rendered sequence, input, interruption, responsive and reduced-motion alternatives, cleanup, and relevant performance. Report specified, prototyped, implemented, and temporally inspected states separately.

## Shared contract

Record these once for each principal sequence, or inherit them from a tested component pattern:

| Decision | Required content |
| --- | --- |
| Object and intention | Persistent identity, visual relationship, and desired feedback, character, continuity, or pleasure. |
| Evidence | Source/timestamps and actual access; distinguish observation from a new design proposal. |
| Trigger and owner | Input, state, route, time, or scroll progress; system responsible for the state and animated property. |
| States and anchor | Resting, active/pending, intermediate, settled, failure/cancel; what remains stable. |
| Choreography | Moving properties, origin, travel, crop, layering, order, overlap, hold, first readability, input readiness, and settlement. |
| Tempo | Candidate duration/easing or measured scroll geometry; provisional until inspected. |
| Interruption | Reverse, rapid repeat, late async result, resize, route exit, and cleanup. |
| Alternate conditions | Keyboard/touch, narrow/short viewport, long content, reduced motion, missing assets, failed enhancement. |
| Proof | Prototype/build identity, actual playback/input conditions, results, limitations. |

For scroll-linked work, define the mapping from start/end geometry to progress. For a bounded sticky chapter, define entry, hold, reverse, and release. A time value alone cannot specify either behavior. Native scrolling can drive expressive choreography without adding a smooth-scroll engine.

For repeated operational work, responsive control feedback and dependable object continuity can create a lively experience. Settings, record lists, and data entry need not run a cinematic entrance on every update. For an expressive page, prototype coordinated section relationships instead of settling for plain scrolling plus generic fade-ups. Choose based on the actual composition and desired experience, not a universal intensity quota.

Read [Motion principles and choreography](motion-principles-and-choreography.md) when the sequence depends on masks, moving type, linked progress, shared media, or expressive staging. Separate recording time, animation time, user progress, and application state. Give the composition a useful/readable state independently of its decorative finish.

## State truth and temporal craft

A prompt visual response may begin immediately while a durable action remains pending. Success must follow the operation's actual outcome, not the end of a tween. Prevent stale completion callbacks from changing a newer state. Define how rapid toggles, rejected moves, canceled uploads, and interrupted drawers settle visually and semantically.

Inspect intermediate contours, clipping, contrast, text readability, and layer intersections. Keep hit areas stable. Coordinate hover, layout, and scroll transforms so they do not overwrite one another. Preserve focus and keyboard/touch access; an equivalent alternative need not copy the same animation.

## Prevent template choreography

A named style, palette, animation library, or spring preset is vocabulary, not a motion concept. For substantial new work, use the chosen product/content relationships to decide what leads, what stays stable, what follows, what can overlap, and where the sequence ends. Do not animate a generic layout into seeming specific.

1. Distinguish marketing demonstration, actual application feedback, and ambient expression. A scripted typing sample or chart loop can explain a product when clearly presented as a demo. It must not impersonate live generation, actual progress, real business figures, or a completed operation.
2. Compare temporal structure across the concept alternatives. If all use the same staggered entrance, floating tiles, count-up, and closing wipe, changing colors or easing has not created another direction. Explore a different object relationship or sequence, not merely more effects.
3. Plan attention across the page. Name a focal region and quiet support for each significant moment. Ambient motion can be beautiful, but should not continually compete with reading, focus, or repeated work. Give loops deliberate boundaries, replay behavior, and applicable pause/reduced-motion handling.
4. Preserve consistent feedback for equivalent controls within a product. Do not randomize button responses or force every section to behave differently. On a narrow repair, retain the approved language and fix the affected behavior.
5. Inspect the principal expressive sequence and a frequent ordinary action at normal speed. Compare their useful/readable state, input readiness, settlement, and repeat behavior. If the composition itself is interchangeable, return to the shared visual brief before tuning durations.

The companion's [UUPM study](https://github.com/MikeyNu/agent-graphic-designer/blob/main/skills/graphic-design/references/template-convergence-study.md) compared 39 gallery previews and twelve full-page compositions. It found recurring visual structures across varied surface styles and also useful exceptions. It did not establish identical animations across the gallery. These motion checks are our design synthesis, not recovered implementation details or a blanket rejection of the examples.

Retain expressive typography, imagery, material, and ornament when they strengthen the actual composition. Replacing a repeated template with obligatory austerity, giant serif type, arbitrary asymmetry, or perpetual cinematic motion is another formula.

## Reference evidence

The owner's references now include 39 distinct still images and nine motion clips. The companion's [timestamped study](https://github.com/MikeyNu/agent-graphic-designer/blob/main/skills/graphic-design/references/owner-motion-study.md) records sampled sequences, detail crops, source identities, and limits. It does not claim continuous playback, source-code inspection, or exact implementation. The clips extend the visual vocabulary without proving that every pictured control works or that all presentation-camera motion belongs in a website.

For video, record file/source identity, duration, dimensions, frame-rate information if available, and access limits. Inspect normal-speed playback and timestamped start/intermediate/settled states. Separate UI movement from presentation-camera motion, cuts, and speed changes. Identify triggers only when supported. If only sampled frames are accessible, report that limitation and do not claim perceived smoothness or an exact easing curve. Transfer relationships into a new prototype rather than copying source assets or asserting its implementation technology.
